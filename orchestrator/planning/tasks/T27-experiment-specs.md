# T27 — Declarative experiment specs & `amp exp run`

- Status: todo
- Phase: 9 (streamlining)
- Depends on: T26, T05
- Environment: sandbox-testable for spec parsing + DAG plan validation (dry-run, no GPU);
  the real pump-grid reproduction needs Bartosz's machine (GPU + native Isaac)

## Goal

A grid/sweep experiment is one YAML file + one command. Replaces `scene-gen/run_grid_4dgs.py`
and `scene-gen/run_grid_seg.py` — including their direct `pipeline.dag.run_dag` bypass,
hand-built run IDs, `force=True` everywhere, and fragmented per-impl CSV outputs.

## In scope

- **Experiment spec schema** (Pydantic-validated, layered like presets via `extends:`), e.g.
  `experiments/pump_grid_v2.yaml`:
  `grid: {base_amp_mm: [...], multipliers: [...], seed}`, `train: {preset,
  sweep_gaussians: [...]}`, `segment: [rigid, rigid2, kabsch, ...]`.
- **`amp exp run <spec>`** drives scene gen → capture (reuse existing capture dir or launch
  new) → convert/train/render sweep → segment with each listed impl → `seg_eval` — as
  orchestrator DAG runs **through `run_pipeline`** (fixing the current `run_dag` bypass and the
  reimplemented seed-then-run logic in `run_grid_4dgs.py`).
- **Run IDs generated by the API** (`<experiment>-<cell>-<8hex>`) replacing hand-built
  `grid-A20mm_M2` / `sweep-...-gN` strings.
- **Capture provenance:** scene-cell params from `grid_manifest.json` are attached to the run
  metadata (today they never enter the run manifest — the capture-provenance gap).
- **`seg_eval_result.json` overwrite hazard fixed:** key results by impl within the run
  (replaces the `_backup_eval()` dance in `run_grid_seg.py`).
- **Content hashing for directory artifacts** — a paths+sizes manifest hash is acceptable — so
  the cross-run stage cache is trustworthy and `force=True` can be retired from batch usage.
  (Generalizes the cache-granularity gap first documented in T11's notes.)
- `amp exp status|list|compare|export` — `export` emits the unified results schema (below).
- Fold `run_grid_4dgs.py` / `run_grid_seg.py` into thin shims over specs, then delete them.
- **Unify the ~20 `runs/*.csv` schemas** into one (`run_id, impl, metric, ...`), keyed
  `(run_id, impl)`, populated via `amp exp export`.

## Out of scope

MLflow logging itself (T28 — but design run metadata so T28 can consume it). Charts (T29).
Hydra migration (rejected). MCP surfaces (T30).

## Deliverables

`pipeline/config/experiment.py` (or equivalent) spec schema, experiment preset/example YAMLs
under `experiments/`, `amp exp` command group bodies, directory-artifact content hashing in the
artifact store, per-impl-keyed seg eval results, unified CSV schema + `amp exp export`,
deleted grid scripts, sandbox tests (spec parsing, layering, DAG plan validation, export
schema), task-log entry on Bartosz's machine for the real pump-grid run.

## Acceptance criteria

- The pump amplitude×multiplier grid + Gaussian-count sweep is reproducible via one spec + one
  `amp exp run` command (real run on Bartosz's machine).
- Results for all segmentation impls land in one queryable store keyed `(run_id, impl)` — no
  per-impl CSV variants.
- No `force=True` in the experiment runner; cross-run stage caching is correct because
  directory artifacts carry content hashes (proven by a sandbox test that changes a file inside
  a directory artifact and observes the cache invalidation).
- Sandbox: full dry-run of a spec → DAG plan validation without GPU.
- `run_grid_4dgs.py` / `run_grid_seg.py` deleted; any surviving references removed.

## Notes / gotchas

The derived-sweep capture dirs (junction-based Gaussian-count subsampling) must keep working,
or be replaced with a cleaner mechanism decided in-task and recorded. The current scripts'
idempotent `already_done()` checks move into the spec runner — but reimplement them on top of
the manifest/caching layer, don't copy the ad-hoc directory-existence checks. The junction
approach is Windows-specific; if it complicates the spec model, a manifest-driven copy/symlink
abstraction is the fallback. Keep experiment specs declarative: no Python in experiment
definitions.
